


FRONTEND REQUIREMENTS DOCUMENT
Jira Clone — Phase 1
React + TypeScript  |  Tailwind CSS  |  @dnd-kit  |  Axios
Backend: Spring Boot on localhost:8080




This Frontend Requirements Document (FRD) is the complete specification for building the React frontend of the Jira Clone Phase 1 application. It defines every screen, every component, every API call, every state shape, and every error handling behaviour so that a developer (or an AI tool like Antigravity) can implement the entire frontend without ambiguity.

The backend is a Spring Boot REST API running on http://localhost:8080. The frontend is a React Single-Page Application (SPA) running on http://localhost:3000. The two communicate exclusively over HTTP/JSON using JWT for authentication.

1.1 What This Document Covers
Complete project folder structure with every file explained
All 5 screens: Login, Register, Projects List, Kanban Board, Issue Detail
Every React component with its props, state, and rendering contract
Every API call: which hook calls it, what data it sends, what it does with the response
Full error handling strategy: what to show when the backend is down, returns an error, or returns unexpected data
JWT authentication: storage, refresh, expiry, logout
Drag-and-drop Kanban board implementation with @dnd-kit
Loading states for every async operation
Form validation rules matching the backend's validation rules
TypeScript type definitions for every API response

1.2 What Is Out of Scope
Phase 2 features: sprints, backlog, comments, file attachments, user roles
Mobile responsiveness (Phase 1 targets desktop browsers at 1280px+)
Internationalisation (English only)
Dark mode (Phase 1 uses light mode only)
Unit tests and integration tests (separate test spec document)

Route: /projects/:projectId/board. Requires authentication. This is the primary working screen of the application.

Layout
AppShell wrapper
Page header: project name (large), project key badge, '+ Create Issue' button (top-right)
4 columns side by side: TO DO | IN PROGRESS | IN REVIEW | DONE
Each column has: a header with the column name and a badge showing the count of issues in that column
Each column renders a scrollable list of IssueCard components
Columns are equal width and fill the viewport height

Loading State
Show skeleton placeholder cards (2-3 per column) while the board data loads
Disable drag-and-drop during loading

Drag-and-Drop Implementation
Use DndContext from @dnd-kit/core wrapping the entire KanbanBoard
Each column is a droppable zone using useDroppable with id = column status string
Each IssueCard is a draggable item using useDraggable with id = issue.id
On drag end (onDragEnd event): identify the source column (active.data.current.status) and the destination column (over.id)
If destination is different from source: call board.store.moveIssue() for optimistic update, then call PATCH /api/projects/{projectId}/issues/{issueId}/status
If PATCH fails: call board.store.revertMove() and show toast error 'Could not move issue. Please try again.'
While the dragged card is being held, apply a shadow and slight scale transform (CSS: scale(1.03), shadow-lg)

Create Issue Modal
Triggered by the '+ Create Issue' button OR a '+ Add issue' link at the bottom of each column
Fields: Title (required, text input), Description (optional, textarea), Type (select: Bug / Task / Story), Priority (select: Lowest / Low / Medium / High / Highest, defaults to Medium), Assignee (optional select dropdown)
Assignee dropdown: populated by GET /api/projects/{projectId}/members — if this endpoint returns an error, the dropdown shows 'Could not load members' and defaults to Unassigned
Submit: POST /api/projects/{projectId}/issues — on success: add to TO DO column via board.store.addIssue(), close modal, show toast 'Issue created'

Reporter — read-only, shows name + avatar initial
Created — formatted date (e.g. 'May 20, 2026')

Auto-Save Behaviour
Title and description save on blur (when the user clicks away)
While saving: show a small 'Saving...' indicator next to the field
On success: show 'Saved' for 2 seconds then hide
On failure: show red 'Save failed' and restore the old value

Delete Issue Flow
'Delete Issue' button opens ConfirmDialog: 'Delete this issue? This cannot be undone.'
On confirm: DELETE /api/projects/{projectId}/issues/{issueId}
On success: close modal, call board.store.removeIssue(), show toast 'Issue deleted'

This is the most important UI safety net. Whenever a page cannot load its data because the backend is unreachable, render BackendDownBanner instead of leaving the user on a broken, empty screen.

Title: 'Cannot Connect to Server'
Message: 'The backend server is not responding. Make sure the Spring Boot application is running at http://localhost:8080 and that CORS is configured correctly.'
Button: 'Retry' — calls window.location.reload()
This component is used on: Projects page, Board page, anywhere a primary data fetch fails with a network error

9.4 JWT Token Expiry Handling
On app startup (main.tsx): call auth.store.initFromStorage()
initFromStorage reads the token from localStorage, calls tokenUtils.isTokenExpired(token)
If expired: call logout() silently — no error shown, just redirect to login on next navigation
If valid: restore isAuthenticated = true and user data from the token payload
